# 从零重建手册

一台**空机器**（内网、无互联网）到**四个租户可用**的完整步骤。每一步都注明"验证方式"，任何一步
不通过就不要往下走。

本文假设部署目录是 `/home/dsh-mt`，与现网一致；换成别的路径时，凡是出现该路径的地方一并替换。

---

## 0. 前置条件

| 项 | 要求 | 怎么确认 |
|---|---|---|
| 操作系统 | 能跑 Docker 的 Linux（现网是内核 3.10 的 RHEL 系） | `uname -r` |
| Docker | 已安装并运行；**最好有 docker-compose**（v2 独立二进制即可，不需要 `docker compose` 插件） | `docker version`、`docker-compose version` |
| firewalld | 已启用（用于租户到宿主的端口隔离） | `firewall-cmd --state` |
| 磁盘 | `/home` 有足够空间（每个租户的数据目录 + 镜像 ~1GB/镜像层） | `df -h /home` |
| 镜像 | **离线环境：镜像必须已经在本机** | `docker images \| grep -E 'dsh-web\|node'` |
| 基础镜像 | `node:22-bookworm-slim`（渲染与运行时都用它） | `docker images node` |

> **为什么强调镜像**：内网 `docker pull` 到不了任何地方。第一次部署前，请在有网的机器上
> `docker save` 出 `dsh-web` 和 `node:22-bookworm-slim`，或让内网 Harbor 上有它们
> （见《管理员手册》§5.5）。

> **这台机器上已经跑着别的 DSH 部署？** 下面这五项**必须全部错开**，否则会互相踩：
> `MT_CONTAINER_NAME_PREFIX`（容器名）、`MT_NETWORK`（网络名）、`MT_BRIDGE_NAME`（网桥名，
> Docker 不允许两个网络同名网桥）、`MT_EDGE_PORT`/`MT_HTTP_PORT`/`MT_EGRESS_PORT`（监听端口），
> 以及租户自己的 `--internal-port`/`--edge-port`（默认从 3181/8091 起，会和已有部署撞车，
> 控制面会因此起不来——`EADDRINUSE`）。

**不要**在共享机器上开着别的 Docker 栈就往下走——本部署会创建 bridge 网络与 firewalld 规则。
先 `docker network ls` 看一眼现有网段，避免冲突。

## 1. 放置代码

```bash
mkdir -p /home/dsh-mt
# 把本项目的 deploy/multi-tenant/ 整个目录内容放进去（bin/ gateway/ node-agent/ model-gateway/
# egress-proxy/ image/ mock-model/ 以及 README.md、管理员手册.md）
cd /home/dsh-mt
ls bin/mt.sh                 # 确认脚本在位
chmod +x bin/*.sh
```

**验证**：`ls bin/ | head` 能看到 `mt.sh`、`render.js`、`registry.js`、`doctor.sh`。

---

## 2. 生成配置

`.env` 是部署的门面，**它不在代码库里**（含凭据），必须新建：

```bash
cat > .env <<'EOF'
# 宿主机对外提供服务的地址（写实际局域网 IP）
MT_BIND_IP=0.0.0.0

# 容器名前缀 / 网络名 / 网桥名：同机多套部署时三项都要错开
MT_CONTAINER_NAME_PREFIX=mt-
MT_NETWORK=mt-net
MT_BRIDGE_NAME=mtdocker0

# 主网络的网段。**强烈建议显式指定**：不写就由 Docker 从默认地址池分配，而共享机器上
# 这些池常被别的栈用光，届时网络根本建不出来（"could not find an available,
# non-overlapping IPv4 address pool"）。隔离租户的网段由渲染自动分配，不用写。
MT_NETWORK_SUBNET=10.97.0.0/16

# 统一入口端口（HTTPS）与运维端口（明文，仅 loopback）
MT_EDGE_PORT=8090
MT_HTTP_PORT=8099
MT_EGRESS_PORT=3128

# 模型上游（公网模型；私有模型见《管理员手册》§3）
# 注意：留空时模型网关会**拒绝启动**（这是设计如此，不是故障）——要在 §4 起完之前配好。
MT_UPSTREAM_BASE=https://api.deepseek.com
MT_UPSTREAM_API_KEY=<管理员提供的模型凭据>

# 出口代理：留空则由 bin/mt.sh up 自动探测并写回
MT_EGRESS_PROXY=

# 运行时镜像（离线环境要先 docker load 或从内网仓库拉）
DSH_IMAGE=dsh-web:local-<标签>
MT_BASE_IMAGE=dsh-web:0.2.0-rc.2

# 日志上限（容器日志与网关自写日志共用这套值）
MT_LOG_MAX_SIZE=10m
MT_LOG_MAX_FILE=3

# 每个租户独立网桥（隔离，见《管理员手册》§7）；不写 = 都放主网桥
MT_TENANT_NETWORKS=all

# 定时备份
MT_BACKUP_INTERVAL_SECONDS=86400
MT_BACKUP_KEEP=7

TZ=Asia/Shanghai
EOF
chmod 600 .env
```

**验证**：`docker run --rm --env-file .env node:22-bookworm-slim node -e 'console.log(process.env.MT_EDGE_PORT)'` 能打印 `8090`。

## 3. 建租户注册表

租户的账号、端口、模型占位 key 都在 `tenants.json` 里，由 `bin/registry.js` 维护。

```bash
bin/mt.sh add alpha --user alice --title "Alpha"
bin/mt.sh add beta  --user bob   --title "Beta"
bin/mt.sh add gamma --user carol --title "Gamma"
bin/mt.sh add delta --user dave  --title "Delta"
```

每个命令会**打印一次初始密码**——记下来交给租户；端口（内部 3181 起、入口 8091 起）自动分配。

> **同机已有部署时**：默认端口会撞车（控制面会因 `EADDRINUSE` 起不来），显式指定错开的端口：
> `bin/mt.sh add alpha --user alice --internal-port 4181 --edge-port 9191`。

**验证**：`bin/mt.sh list` 出现四行，各有端口与用户。

---

## 4. 首次启动

```bash
bin/mt.sh up
```

它会依次：填充占位 key → 渲染 `docker-compose.yml` → 构建网关/出口代理/模型网关 → 启动全部容器
→ 探测出口代理地址 → 应用隔离规则 → 注册运行时 → 等就绪 → 打印入口地址。

**验证**：

```bash
bin/mt.sh ps        # 8 个容器都在跑
bin/mt.sh runtimes  # 4 个租户都注册了
bin/mt.sh url       # 打印入口
```

常见失败：
- `找不到 node:22-bookworm-slim` → 基础镜像没导入（§0）；
- 某个租户 `不 ready` → `bin/mt.sh logs <租户>` 看它为什么没起来。

## 5. 传输加密（可选但建议）

```bash
bin/mt.sh cert <宿主IP>     # 生成自签 CA 与服务器证书
bin/mt.sh up                # 重新渲染，公开端口转为 HTTPS，另开 loopback 明文运维端口
bin/mt.sh url               # 入口变成 https://
```

**验证**：`curl -sS -o /dev/null -w '%{http_code}' --cacert state/tls/ca.crt https://<宿主IP>:8090/` 返回 200。

客户端首次访问会有证书告警（自签），把 `state/tls/ca.crt` 导入信任即可。

---

## 6. 隔离规则

`bin/mt.sh up` 已经跑过一次 `isolate apply`，这里确认它**覆盖了每个网桥**：

```bash
bin/mt.sh isolate status
```

期望：`已启用，覆盖全部 N 个网桥，运行时已加载`。**新增租户后必须再跑一次** `bin/mt.sh isolate apply`
（新租户会多一个网桥）。

**验证**（实测租户确实出不去）：

```bash
docker exec mt-dsh-alpha node -e "
const net=require('node:net');const s=net.connect({host:'<宿主IP>',port:22,timeout:2000})
s.on('connect',()=>{console.log('可连 ✗');s.destroy()})
s.on('timeout',()=>{console.log('被丢弃 ✓');s.destroy()})
s.on('error',()=>console.log('被丢弃 ✓'))"
```

## 7. 模型接入

管理员在 `.env` 里配 `MT_UPSTREAM_BASE` / `MT_UPSTREAM_API_KEY`，**真凭据只进模型网关容器**；
每个租户容器里只有形如 `sk-mt-<租户>-…` 的占位 key。

```bash
bin/mt.sh model-check --tenant alpha --user alice --password <密码> --prompt "reply ok"
```

**验证**：输出里有 `实际使用的模型: <模型名> ✓`。

## 11. 多机（可选）

如果租户要跑在别的机器上，在那台机器上：

1. 放同一份代码（§1）；
2. 从控制面取 `tenants.json` 与 `state/registry.key`；
3. `MT_NODE_NAME=<节点名> bin/mt.sh up` —— 只创建分配给该节点的租户
   （控制面用 `bin/mt.sh add <租户> --node <节点名>` 指定）；
4. 起节点代理（见 README §1.1）。

**验证**：控制面 `bin/mt.sh runtimes` 里该租户的节点名是新的那台。

---

## 12. 从备份恢复整套

```bash
bin/mt.sh restore backups/dsh-mt-<时间戳>.tar.gz
bin/mt.sh up
```

恢复是**非破坏性**的：现有数据先挪到 `restore-aside-<时间戳>/`。详见《管理员手册》§5。

## 附：这台现网机器的事实（供对照）

| 项 | 值 |
|---|---|
| 部署目录 | `/home/dsh-mt`（根分区只有 50G，数据放在 `/home`） |
| 内核 | 3.10（DSH 自带的文件沙箱跑不了，容器是唯一边界） |
| `net.ipv4.ip_forward` | **0** → bridge 发布端口在局域网不可达，所以控制面/出口代理/模型网关都用 host 网络 |
| 网桥命名 | 主网桥固定 `mtdocker0`；每个隔离租户 `mtbr<hash>` |
| 租户网段 | `10.98.<哈希> .0/24`（显式分配：默认地址池已被宿主上其它栈耗尽） |
| 隔离 | firewalld INPUT_direct 规则，按每个网桥各自一条放行（3128）+ 一条丢弃 |
