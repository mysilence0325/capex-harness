# 使用说明

面向两类人：**租户用户**（用自己的账号进来干活）和**管理员**（管租户、看状态、做维护）。

- 部署（从零装一套）：见《从零重建手册》
- 运维细节（模型、备份、升级、告警、排障）：见《管理员手册》
- 本文只讲**怎么用**，以及每条用法**在什么条件下成立**。

## 一、先知道入口在哪

| 入口 | 地址 | 谁能用 |
|---|---|---|
| 统一登录入口 | `https://<部署机 IP>:8090/` | 所有租户，登录后自动进入自己的空间 |
| 租户专属入口 | `https://<部署机 IP>:8091/`（第二个租户 8092，依次类推） | 该租户，省去选择步骤 |
| 域名入口 | `https://<租户名>.dsh.local:8090/` | 该租户；需要客户端 hosts 指向部署机 |
| 管理控制台 | `https://<部署机 IP>:8090/__mt/admin` | 管理员，**局域网里任何一台机器都能开**（HTTPS） |
| 管理控制台（本机便利入口） | `http://127.0.0.1:8099/` | 只在部署机上（明文、仅 loopback；日常用上面那条 HTTPS 的） |

**证书是自签的**，浏览器第一次会报"不安全"。这不是配置漏了，是内网部署的常态；要消掉它就得
把 CA 装进每台客户端（见《管理员手册》§5）。

## 二、租户用户：你会做什么

### 2.1 登录
打开统一入口，选自己的租户（或用专属入口），用管理员给你的用户名和口令登录。

登录后看到的是 **DSH 的工作界面**：会话、文件、模型都在里面。你能用哪些模型由管理员统一配置，
你这边不需要填任何 API key —— 模型请求会经部署的模型网关转发，密钥不会出现在你的浏览器里。

### 2.2 改自己的密码
界面上有**改密码**入口（与登录同一个入口下的账号页）。要求：当前密码 + 新密码（至少 12 位）。

**改完之后**：
- 新密码立刻生效，旧密码立刻失效（实测：新密码登录 303、旧密码 401）
- 你在**其它地方已登录的会话会被踢掉**，当前这次保持登录 —— 这是设计如此

忘了密码只能找管理员：管理员可以在部署机上重置（见《管理员手册》§2.2）。

### 2.3 你的空间里有什么
- 会话记录、上传的文件、工作区数据，都在你自己租户的目录下，**别的租户看不到**
- 每个租户的网络是**独立隔离**的：你的容器连不到别人的容器，也连不到部署机的内部端口
- 容器内可以自由操作（内网部署按"完全可信租户"配置），真正的边界是容器 + 网络隔离 + 系统调用限制

### 2.4 配额与限速（如果管理员设了）
管理员可以给你设**磁盘配额**（你的目录最多占多少）和**网络限速**（上行 / 下行 / 双向）。
它们的效果：
- 配额：达到上限后**写入会失败**，需要清理或请管理员调高
- 限速：超出速率会被**丢包**，你会感到变慢 —— 这是限速在工作，不是故障

配额**是否强制**取决于文件系统有没有开启项目配额（见《管理员手册》§6.0）。没开启时管理员只能
记录"打算给你多少"，指标与告警照常工作，但**不会真的拦住**写入。

### 2.5 模型用量的可见性
管理员可以用 `bin/mt.sh usage` 看每个租户调了多少次模型、用了多少 token（含 `--csv`）。
**费率不在部署里** —— 那是管理员的商业决定，工具只出用量。

## 三、管理员：日常用的命令与界面

### 3.1 一分钟确认部署是好的
```bash
cd /home/dsh-mt
bin/mt.sh doctor          # 全量体检，看最后一行"0 项失败"
bin/mt.sh acceptance      # 68 项验收（含控制台各项能力），失败会退出码 1
bin/mt.sh acceptance --self-test   # 证明这套检查本身会失败，不是只会说好话
```

### 3.2 看租户和入口
```bash
bin/mt.sh list            # 租户清单
bin/mt.sh runtimes        # 每个租户注册到控制面的运行时地址
bin/mt.sh usage           # 模型用量（--csv 可导出）
```

### 3.3 管理账号
```bash
bin/mt.sh admin-users                       # 有哪些管理员、什么角色
bin/mt.sh admin-add <名字> --role admin     # 加管理员（--role viewer 是只读）
bin/mt.sh admin-remove <名字>               # 删除（拒绝删掉最后一个管理员）
bin/mt.sh admin-passwd <名字>               # 重置某个管理员的密码
```

**控制台里也能做**（浏览器打开 `https://<部署机 IP>:8090/__mt/admin`，局域网任意机器）：租户增删、启停、改密、
配额与限速、租户导出/导入、操作历史（可按租户筛选、按时间范围查、翻页）、两步验证。

注意：**一个租户只有一个登录账号**；一个团队多人共用一个租户时，他们共用该租户的会话空间与工作区，彼此没有隔离。
给一个团队**再开一个互相隔离的空间**，做法是新增一个租户。

### 3.4 管理员的两步验证（MFA）
控制台里"两步验证"卡片：

1. 点**开始绑定** → 得到一串密钥和一条 `otpauth://` 链接
2. 把它加进验证器应用（没有二维码，手抄密钥或粘贴链接都行）
3. 输入验证器当前的六位码 → **确认并开启**

**要点**：
- 没确认之前**不算开启**，密钥随时可以重来 —— 不会把人锁在外面
- **恢复码只在开启时显示一次**（10 个，每个只能用一次），当场存好
- 恢复码用完或想换：卡片里输当前验证码 → **重新生成恢复码**（旧的立刻作废）
- 关闭：输当前验证码（或用一个恢复码）→ **关闭两步验证**
- 忘了验证器又没有恢复码：在部署机上 `bin/mt.sh admin-mfa remove <名字> --yes`

命令行等价做法：`bin/mt.sh admin-mfa setup|confirm|status|remove <名字>`。

### 3.5 配额与限速
控制台卡片或命令行都能设：

```bash
bin/mt.sh bandwidth set <租户> 10mbit --up|--down|--both   # 网络
bin/mt.sh bandwidth show                                    # 看当前规则与计数器
bin/mt.sh bandwidth clear <租户>
bin/mt.sh quota set <租户> 2g                               # 磁盘
bin/mt.sh quota check                                       # 这台机器能不能强制配额
bin/mt.sh quota clear <租户>
```

**限速是运行时规则**：容器重建后会丢。`bin/mt.sh up` 会按 `state/bandwidth.json` 里的意图
自动恢复，所以设完不用手工记。

### 3.6 备份、导出与恢复
```bash
bin/mt.sh backup                      # 整套备份（含 .env、注册表、租户数据、state）
bin/mt.sh export <租户>               # 单个租户导出成可移植归档（0600）
bin/mt.sh import <归档> --as <新名>   # 导入为新租户（口令不变，端口自动分配）
bin/mt.sh restore <归档>              # 整套恢复：**会覆盖 .env**，覆盖前会告诉你哪些键会丢
bin/mt.sh restore <归档> --yes        # 跳过那个确认（脚本化时用）
```

**恢复之前先看它的提醒**：它会列出"恢复后会消失的配置键"，并把当前 `.env` 另存一份。

### 3.7 告警
本部署自带接收器：告警写进 `state/alerts/alerts.jsonl`，同时打到容器日志。

```bash
bin/mt.sh alert-sink status   # 接收器状态、Alertmanager 的接收人、最近收到的告警
bin/mt.sh alert-sink test     # 投一条测试告警并验证真的落盘
```

**要有内网告警平台，改一行即可**：`/home/capex-ai-lab/deploy/private/alertmanager/alertmanager.yml`
里那个 `url:` 换成平台的地址（详见《管理员手册》§4.3）。

## 四、这份部署**不**包含什么（免得你以为有）

- **SSO / LDAP**：没有接。账号是本地的，管理员手工加。
- **租户级 MFA**：两步验证只有**管理员**有；租户用户只有口令。
- **计费 / 费率**：只出用量，不算钱。
- **真机多节点验证**：协议支持多节点且已用第二个节点名在同机验证过，**但没有在第二台真机上跑过**。
- **租户级磁盘 I/O 限速**：在这台机器上实测**不生效**（原因见《管理员手册》§6.0.3），
  所以默认关闭；能生效的是**配额**（限总量，不限速率）。
- **单点**：控制面与每个租户容器都是单实例，靠 `restart: unless-stopped` 自愈。
- **静态加密**：会话、凭据与备份都是明文（靠 0600 权限），没有 KMS 或密钥托管。
- **离线镜像仓库**：`bin/mt.sh registry-push` 依赖的内网 Harbor 当前不可用（`18083` 连不上），
  所以现在搬镜像只能用 `docker save` / `docker load`；`bin/mt.sh doctor` 会报出这个状态。
- **一个租户一个账号**：没有"同一租户下多个用户"这回事；要隔离就再开一个租户。
